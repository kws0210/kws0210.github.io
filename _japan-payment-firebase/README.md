# 일본 결제 도우미 Firebase 설정

화면은 `japan-payment/index.html` 단일 파일이며 GitHub Pages에서 제공한다.
Firebase 웹 SDK 12.19.0의 Authentication과 Firestore Lite를 브라우저에서 사용한다.
전용 프로젝트 ID는 `kws0210-japan-payment`이며 Firestore 기본 데이터베이스는 서울(`asia-northeast3`)의 무료 등급이다.
웹앱 연결 설정은 HTML의 `firebase-config` JSON에 있다.
웹앱의 공개 API 키는 서버 관리자 인증정보가 아니다.
CLI 로그인 정보와 서비스 계정 키는 저장소에 추가하지 않는다.

## 저장 및 로그인

사용자 선택에 따라 문자 인증이나 비밀번호 없이 전화번호만 입력한다.
번호를 아는 사람은 같은 기록을 조회·조정할 수 있다.
국내 번호와 `+82` 표기를 정규화한 뒤 SHA-256으로 계정 문서 ID를 만든다.
Firebase에는 원문 전화번호를 저장하지 않는다.
이 해시는 전화번호 소유를 인증하거나 번호 추측을 막는 비밀번호가 아니다.

`paymentAccounts/{번호 해시}`에 카카오페이·KB 결제 할인 및 돈키호테 최대 7% A+ REWARDS 매장 쿠폰 사용 횟수와 버전을 저장한다.
매장 쿠폰은 `donkiCoupon` 필드에 누적 사용을 기록하며 기존 계정에서 없는 필드는 0으로 읽는다.
제공된 약관은 거래당 1회로 전체 사용 한도는 명시하지 않는다.
누적 횟수로 소진 처리하지 않으며 매번 앱에서 유효한 쿠폰인지 확인한 거래만 포함한다.
새 화면의 첫 변경 시 기존 결제 횟수를 보존한 채 필드를 추가하며 일괄 데이터 이관은 필요하지 않다.
추천 조합의 결제·매장 쿠폰 횟수는 한 트랜잭션에서 함께 반영한다.
이미 추가된 쿠폰 필드를 이전 화면이 생략하는 쓰기는 거절하므로 기존 탭은 새로고침해야 한다.
하위 `operations/{요청 ID}`는 횟수와 함께 트랜잭션으로 기록해 통신 오류 후 같은 요청을 다시 보내도 중복 계산하지 않는다.
Firestore Lite는 카운트를 디스크에 캐시하지 않는다.
브라우저에는 Firebase 익명 인증 정보와 계정 해시·마스킹한 번호만 자동 로그인용으로 남긴다.
로그아웃은 이 브라우저의 로그인 정보와 표시 상태만 해제한다.
서버 기록은 삭제하지 않으며 같은 번호로 다시 로그인하거나 다른 기기에서 접속하면 다시 조회한다.

기존 로컬 카운트는 사용자가 확인한 경우에만 아직 사용 기록이 없는 번호로 가져온다.
가져오기 또는 가져오지 않기를 결정하기 전까지 기존 로컬 기록을 보존한다.
기존 환율 캐시는 제거하며 새 버전은 페이지 시작·복귀 시 환율을 조회한다.
계산에 50달러 기준 환율이 필요하면 진행 중인 조회를 기다리고, 없거나 자동 환율이 30분 이상 지났으면 자동 조회한 뒤 계산한다.
Frankfurter 조회가 6초 내 완료되지 않거나 잘못된 응답을 주면 ExchangeRate-API로 재시도한다.
제공처·기준일을 표시하며 기준일이 7일을 넘긴 응답은 사용하지 않는다.
두 제공처가 모두 실패하고 유효한 기존 환율도 없으면 추천·횟수 반영을 하지 않으며 연결 확인·재시도·직접 입력을 안내한다.
자동 조회 중 직접 입력한 환율이 있으면 이전 요청을 취소하고 직접 입력을 우선한다.
카카오페이 1회·KB 3회에서 증가 버튼, 0회에서 감소 버튼을 비활성화한다.
매장 쿠폰 누적 횟수에는 1회 소진 제한을 적용하지 않고, 저장 정수 상한은 1,000,000이다.
카카오 최대 7%의 구간 할인율은 제공된 약관에 없어 설정의 `kakaoRateLow`(10,000~29,999엔)·`kakaoRateHigh`(30,000엔 이상)에 확인한 비율을 한 번 저장한다.
0은 미확인이며 해당 구간의 매장 할인액을 합산하지 않는다.
UnionPay 전용 매장 쿠폰은 공식 10,000~29,999엔 5%·30,000~49,999엔 7%로 자동 계산하고 50,000엔 이상 구간은 추정하지 않는다.
최대 7% 약관의 알리페이 중복 허용만으로 현재 2,000엔 쿠폰의 개별 제외 조건까지 확정하지 않는다.
카카오페이 최대 7%와 2,000엔은 정확한 중복 근거를 확보하지 못해 각각 비교하며 합산하지 않는다.
이용자가 중복 여부를 판단하는 설정은 제거했다.
KB 1002289 공식 행사에서 안내하는 유니온페이 전용 매장 쿠폰은 `unionStoreCoupon`으로 보유 여부를 저장하며 카카오페이 A+ 쿠폰과 섞지 않는다.
입력한 세금 제외·쿠폰 할인 전 금액으로 총 할인율을 구하고, 쿠폰 할인 후 금액으로 결제 할인 최소 금액과 한도를 판단한다.
KB 20달러 한도는 최신 조회 환율로 반영한다.
노리 유니온페이는 예시 상품 가정을 유지하고, 사용자가 정정한 트래블월렛 엔화 잔액 결제로 비교한다.
KB 이용료 0.25~1.05% 예상 범위와 트래블월렛 공식 엔화 환전·해외 결제 수수료 0%를 반영한다.
기존 `travelCard` 보유 설정과 `travel` 계산 키를 유지해 번호별 설정·사용 기록을 초기화하지 않는다.
수수료·실제 원화 환율 입력란은 없으며 확인한 이용료를 자동 계산한다.
KB는 예상 범위 상한 1.05%를 할인 후 결제액에 적용하고, 예상 할인액에서 차감해 추천 순서를 정한다.
트래블월렛 엔화 결제는 환전·해외 결제 수수료 0%를 적용한다.
카카오페이는 제휴사 수수료가 적용 환율에 포함되어 해당 비용을 null로 유지한다.
카카오 후보가 있으면 이 미확인 비용을 더하지 못한 잠정 비교이며 0원으로 확정하지 않는다.
실제 청구·충전 환율 차이는 미반영이고 원화 총지출을 확정하지 않는다.
이전 요청의 수동 환율 옵션은 추천에 반영하지 않으며 [FEES.md](FEES.md)에 공식 근거·계산 제약을 보존한다.
준비 가이드는 8개 접힌 준비 목록과 스크린샷 10장으로 구성하고 긴 중복·수수료·점포 근거는 `/japan-payment/basis/`에 둔다.
기존 prepare/#stack-evidence·prepare/#payment-costs는 대응하는 basis 앵커로 이동하며 작업 항목 직접 링크는 상위 details를 자동으로 펼친다.
KB 10%·돈키호테 500엔·4,000엔 즉시 할인은 합산하지 않고 가장 큰 하나만 선택한다.
`unionDonki500`·`unionDonki4000`은 각 3회 사용 기록이며 KB 공통 `union` 3회와 분리한다.
4,000엔 별도 등록은 `unionDonki4000Registered`에 저장한다.
돈키호테 선택 시 공식 오사카 46개 지점을 한국어·일본어 이름으로 검색·선택하는 팝업을 연다.
지점 라디오를 고른 뒤 ‘확인’으로 적용하며 선택 전에는 ‘확인’을 비활성화한다.
‘모름’은 미확인 지점으로 적용하며 검색·임시 선택만으로는 기존 지점이나 사용 횟수를 바꾸지 않는다.
선택한 공식 점포 ID `options.donkiStoreId`로 행사 대상 15곳 여부를 판단하고 `options.donkiStoreGroup`을 파생한다.
선택 지점은 계산 화면과 결과에 표시하며 `osaka-listed`인 거래만 500엔·4,000엔을 비교한다.
그 외·미확인은 전용 두 행사만 제외하며 지점 선택은 계산·장소 변경·로그아웃 뒤 초기화한다.
이전 요청 기록과의 호환을 위해 지점 ID 없는 요청의 기존 그룹 옵션은 유지한다.
공식 점포 API의 전체 115곳과 돈키호테 오사카부 46곳을 대조했다.
페이지 최초 8개만 전체로 오인한 가이드는 정정했고 [OSAKA_STORES.md](OSAKA_STORES.md)에 대조 표를 보존한다.
공항은 장소와 금액만 입력하고 보유 설정으로 자동 비교한다.
그 외에서만 `unionAccepted`로 매장의 유니온페이 결제 가능 여부를 확인한다.
돈키호테 쿠폰·전용 행사는 다른 매장에 적용하지 않는다.
`paymentAccounts/{account}/daily/{일본 YYYY-MM-DD}`에 `unionDonki500`·`unionDonki4000`의 0/1 기록을 카운트 변경과 같은 트랜잭션으로 저장한다.
오늘 사용한 전용 혜택을 재추천하지 않고 일본 자정 이후 새 날짜 문서를 사용한다.
수동 +는 오늘 사용 1회, −는 오늘 기록 0회로 반영해 재계산 시 복원한다.
앱 바깥의 실제 결제나 기능 도입 전 당일 사용을 조회하지 않으며 잔여 행사 예산은 보장하지 않는다.
`donkiCoupon`은 발급 경로와 관계없이 선택한 매장 쿠폰의 누적 사용 기록이다.
공식 링크와 현재 약관 근거는 `/japan-payment/prepare/#union-donki`에 둔다.
상단 설정에서 보유 카드·결제 쿠폰·매장 쿠폰·사전 등록과 확인한 구간 할인율을 저장한다.
`kakaoStackConfirmed`·`unionDonkiEligible`는 기존 Firestore 문서 호환용으로만 남기고 추천에 사용하지 않으며 설정을 저장하면 false로 기록한다.
설정은 `paymentAccounts/{account}/preferences/current`에 `settings`와 증가하는 `revision`으로 저장하며 브라우저에는 저장하지 않는다.
구버전 보유 설정은 새 대상 점포 false·구간 할인율 0으로 읽어 기존 카드·쿠폰·횟수를 보존한다.
한 번 새 설정을 저장한 뒤에는 구버전 폼이 새 항목을 누락해 지우는 쓰기를 거절한다.
기존 계정도 보유 여부를 추정하지 않고 첫 설정을 저장해야 계산할 수 있다.
로그인·복원 시 설정을 함께 읽고 계산 트랜잭션에서도 최신 설정을 읽어 보유하지 않은 항목을 제외한다.
설정 저장은 카운트 문서를 수정하지 않으며 이전 화면의 계산도 설정을 누락해 지울 수 없다.
동시에 설정을 수정하면 revision 충돌을 안내하고 최신 설정을 다시 표시한다.
추가 결제 할인이 없으면 보유한 트래블월렛 카드를 우선하고, 없으면 보유한 KB 카드·일본 페이머니의 일반 결제로 안내한다.
일본 페이머니 준비·2,000엔 쿠폰 보유·카카오 미사용이면 돈키호테 17,000엔의 2,000엔 결제 할인을 비교에 포함한다.
결과에 계산 전 혜택 횟수와 보유·등록·최소 금액 상태를 표시한다.
횟수 조정이나 다른 기기의 설정·횟수 변경을 동기화하면 이전 결과를 숨기고 재계산을 안내한다.
기존 한도 초과 기록은 감소시킬 수 있다.

## 설정 및 배포

Firebase Authentication에서 기본 서비스를 시작하고 익명 로그인 제공자를 활성화한다.
인증 허용 도메인에 `kws0210.github.io`를 등록한다.
유료 Identity Platform 전환이나 문자 발송 기능은 사용하지 않는다.

규칙은 이 디렉터리에서 배포한다.

```sh
npm install
npx firebase deploy --only firestore:rules --project kws0210-japan-payment
```

규칙은 인증 없는 접근, 전체 목록 조회, 계정 삭제, 한도 초과 증가, 요청 기록 덮어쓰기를 막는다.
번호를 입력한 사람이 기록을 여는 서비스 정책에 따라 익명 인증한 이용자는 알고 있는 계정 문서에 접근할 수 있다.
이 디렉터리는 밑줄로 시작하므로 GitHub Pages의 기본 Jekyll 게시 대상에서 제외된다.
기존 홈과 다른 리포트는 변경하지 않는다.

## 검증

Node.js 22와 Java 21 이상에서 로컬 에뮬레이터를 실행한다.

```sh
npx firebase emulators:start --only auth,firestore --project demo-japan-payment
```

다른 터미널에서 저장 규칙 검증을 실행한다.

```sh
npm run test:rules
npm run test:recommendation
```

브라우저 검증 시에만 localhost HTML에 `firebase-emulator` 메타 태그를 `true`로 주입하고 프로젝트 ID를 `demo-japan-payment`로 설정한다.
공개 페이지는 에뮬레이터에 연결하지 않는다.
